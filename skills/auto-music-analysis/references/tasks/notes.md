# Transcribe a pitched part

Identify the desired part and output format when ambiguous. When a score is requested, follow [manual score authoring and event review](score-export.md): the agent must cross-check and explicitly write every note and rest. Analysis backends provide candidate evidence only, never a score to import or automatically clean up. Prefer a suitable [isolated stem](../tools/audio-separator.md) for optional [Basic Pitch](../tools/basic-pitch.md) candidates; [Omnizart](../tools/omnizart.md) and authorized [Klangio](../tools/klangio.md) jobs are alternatives with different instrument/output coverage.

Preserve raw notes, onset/offset seconds, pitch representation, bends where supported, and unvoiced/unknown spans. A pitched-note model does not independently assign every note in a mix to its real instrument or establish the intended main melody.

For a complete main-vocal candidate, distinguish source identity, framewise pitch, and note boundaries. [pYIN](../tools/librosa-pyin.md) is a locally executed F0 option; its fast execution does not solve accompaniment leakage or same-pitch syllable segmentation. Compare one representative vocal passage and an instrumental passage before processing the whole recording. Do not keep tuning a foreground-suppression method that demonstrably follows instruments. [Tony](../tools/tony.md) is a candidate for subsequent interactive correction.

For vocal scores with lyrics, follow [manual lyric verification and placement](score-export.md#manually-verify-and-place-lyrics). The agent must verify each character/syllable and its note correspondence, then explicitly write it into the score. Do not use automatic models, forced alignment, or scripts to assign words to notes, and do not infer note boundaries from lyric count.

Cover the requested time range with explicit review status and unresolved spans when the user prefers a candidate. Distinguish a verified rest from an unknown or unvoiced interval; never write a rest solely because pitch detection failed. State that timeline coverage is not recovery of every sung note. For numbered notation, keep the tonic reference and octave convention explicit, retain chromatic notes, and use the manually authored score as the source for text, visual score, MIDI, and MusicXML. Keep pre-grid audio and final layout padding separately accounted for.

For notation follow [score assembly](score-export.md), including [tempo](tempo.md) and [meter](meter.md). Guitar strings/frets need manual tuning and fingering decisions; distinguish a suggested playable arrangement from the original performance. Do not generate or clean up score events with temporary code or claim recovered fingering from MIDI alone.
